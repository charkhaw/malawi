## 3.1 Automatic modular laser personalization systems

| Requirement | Technical reasons supporting compliance | Cross-references |
|---|---|---|
| **3.1.1** Two automatic modular laser personalization systems for polycarbonate cards. | Complies. Two automatic modular laser personalization systems are supplied, installed and commissioned, each a complete line from blank card feeder to verified output on 100% polycarbonate cards. As clarified in the Response to Clarifications 001, the cards are chipless, and the modular platform keeps provision for chip encoding should NRB adopt chip-based cards later. | System Architecture Sections 1.1 and 3.1; Attachment: Laser personalization system datasheet |
| **3.1.2** Duplex printing speed of at least 2,000 cards per hour across two machines. | Complies. As clarified in the Response to Clarifications 001 and the Responses to Queries 003, 2,000 cards per hour is the combined output of accepted finished cards, at least 1,000 per machine. Each machine, rated up to 2,000 cards per hour, personalizes both faces in one pass, and the rate is measured at factory acceptance with full personalization content. | System Architecture Sections 3.5 and 11.1; Preliminary Project Plan Section 4.3; Attachment: Laser personalization system datasheet |
| **3.1.3** Laser engrave text, greyscale picture and stacked-layer security features including CLI, QR code and tactile printing. | Complies. Each card is laser engraved on both faces with variable text, a greyscale portrait, secondary image, micro lettering, CLI, a QR code carrying both alphanumeric values, and tactile laser printing. Each feature is engraved as a stacked layer at a controlled depth within the fused polycarbonate body, so altering one disturbs the others. | System Architecture Sections 3.2 and 6.7; Preliminary Project Plan Section 4.3; Attachment: Laser personalization system datasheet |
| **3.1.4** Personalization systems produce multilingual identity documents. | Complies. As clarified in the Responses to Queries 003, card text is in English and Chichewa, and the System engraves both as the approved layout requires. Data is held in Unicode throughout, and the characters used in Chichewa text are profiled against the card layout during discovery. | System Architecture Sections 3.2, 4.4 and 6.13; Preliminary Project Plan Section 2.3 |
| **3.1.5** In-line verification of personalized card data, including verification of the optical data. | Complies. Every card is verified in the production path before it leaves the machine: engraved text is read by optical character recognition and verification, and the QR and other machine-readable codes are read and compared with the prepared record, on both faces. Verification covers every card, not a sample. | System Architecture Sections 3.6 and 6.8; Attachment: Laser personalization system datasheet |
| **3.1.6** Automatic blank card recognition against reference, with independent X-Y alignment for front, back and CLI. | Complies. Before marking, the system identifies each blank card body and checks it against the card reference for the job, rejecting a mismatched body before any data is applied. X-Y alignment is performed independently for the front, the back and the CLI feature, registered to the pre-printed body and the lenticular structure. | System Architecture Section 3.6; Preliminary Project Plan Section 4.3 |
| **3.1.7** Automatic rejection of bad cards and in-job automatic or manual reproduction, notified by message. | Complies. Cards failing verification are rejected automatically and recorded against the job with the card, the point of failure and the reason, and the operator is notified by an on-screen message. Reproduction takes place within the same job, automatically or on operator instruction, without stopping production. | System Architecture Sections 3.7 and 6.8; Preliminary Project Plan Section 4.3 |
| **3.1.8** GUI machine software for record status retrieval, with audit, XML or flat files per job or batch. | Complies. The graphical machine software lets staff retrieve the status of each record in a job, and the Printer Control Service writes that status to the production database for publication to NRIS. On completion of each job or batch, the machine generates audit, XML or flat-file output recording the outcome of every record. | System Architecture Sections 3.9 and 6.6 |
| **3.1.9** Emergency buttons around the machine, reachable by the operator from each point. | Complies. Emergency stop buttons are positioned around each machine so that the operator can reach one from every point at the line. Emergency stops are tested at factory acceptance, and every operator is trained and assessed on reaching and operating them from the working position. | System Architecture Section 3.1; Preliminary Project Plan Sections 3.8 and 4.3; Attachment: Laser personalization system datasheet |
| **3.1.10** Modular machine allowing future expansion and upgrades. | Complies. Each machine is a modular platform: laser stations and processing modules are added or reconfigured on site without returning the machine to the factory. The platform accepts up to four laser modules and chip encoding modules, keeping the line compatible with future chip encoding mandates, as the Responses to Queries 003 require. | System Architecture Section 3.1; Attachment: Laser personalization system datasheet |
| **3.1.11** Fiber-optic or diode-based laser and greyscale printing technology for polycarbonate card personalization. | Complies. Marking uses Master Oscillator Power Amplifier fiber laser technology with greyscale printing, applied to 100% polycarbonate cards. Engraving carbonizes material within the card body, so personalized data cannot be removed or altered without visible damage. As clarified in the Response to Clarifications 001, the cards are chipless. | System Architecture Sections 3.1 and 3.2; Attachment: Laser personalization system datasheet |

## 3.2 Personalization laser features

| Requirement | Technical reasons supporting compliance | Cross-references |
|---|---|---|
| **3.2.1.1** Graphical layout designer to create, modify and manage card personalization layouts. | Complies. The graphical Card Layout Template Editor, supplied with the manufacturer's personalization software, creates, modifies and manages card layouts. Templates are versioned and approved before production use, and each card records the template version that produced it. As clarified in the Responses to Queries 04, it is used to redesign the Malawi National ID template with NRB. | System Architecture Sections 6.3 and 13.1; Preliminary Project Plan Section 2.4 |
| **3.2.1.2** Editor configures text, images, CLI windows, micro-text, MRZ and QR zones and all variable elements. | Complies. The editor configures text fields, portrait and signature images, the CLI window, micro-text zones, MRZ and QR zones, the card identifier zone and tactile regions, fixing the position of every variable element. The production path binds data into these elements and cannot move, resize or remove them. | System Architecture Section 6.3 |
| **3.2.2.1.1** Picture marking resolution of 600 dpi or higher, in greyscale as amended. | Complies. As amended by Addendum No. 2, the portrait is marked at 600 dpi or higher in greyscale. Continuous tone is produced by varying the laser energy density at each addressed point, and the resolution is measured on produced cards at factory acceptance. | System Architecture Sections 3.2 and 3.3; Preliminary Project Plan Section 4.3 |
| **3.2.2.1.2** Micro text at 600 dpi or higher, with 0.33 mm line width and height. | Complies. Micro text is marked at 600 dpi or higher at a line width and height of 0.33 mm, using a focused laser spot well below that dimension and beam positioning repeatable enough to place successive characters without drift. The resolution is measured on produced cards at factory acceptance. | System Architecture Section 3.3; Preliminary Project Plan Section 4.3 |
| **3.2.3.1.1** Integrated dedicated laser marking unit. | Complies. The marking subsystem is integrated into each personalization machine and includes a dedicated laser marking unit, with fiber laser engraving modules in a protected laser marking chamber performing all marking on both faces of the card. | System Architecture Section 3.1; Attachment: Laser personalization system datasheet |
| **3.2.3.1.2** Power supply and control PC for laser and greyscale personalization. | Complies. Each machine includes its power supply and an industrial control PC for laser and greyscale personalization, which runs the machine software, drives the laser stations and connects to the production network over Ethernet. | System Architecture Sections 3.1 and 3.9; Attachment: Laser personalization system datasheet |
| **3.2.3.1.3** Integrated cooling system for continuous industrial-scale laser engraving. | Complies. An integrated cooling system in each machine maintains laser operating temperature under continuous industrial duty, and the machines are rated for 24/7 operation. Cooling is serviced at the manufacturer's preventive maintenance intervals. | System Architecture Section 3.1; Preliminary Project Plan Section 5.4; Attachment: Laser personalization system datasheet |
| **3.2.3.1.4** All components fully integrated, operating as a unified system with synchronized workflow control. | Complies. The laser marking unit, power supply, control PC and cooling system are fully integrated into the personalization machine rather than assembled from separate units, and operate as a single system under synchronized workflow control. | System Architecture Section 3.1 |
| **3.2.4.1.1** Calibration tool adjusting individual or all laser units for uniform marking quality. | Complies. Each machine includes a laser calibration tool that adjusts an individual laser station or all stations simultaneously. All stations are calibrated to a common reference, so marking quality is consistent across the line and cards marked by different stations in the same job are indistinguishable. | System Architecture Sections 3.8 and 6.7; Preliminary Project Plan Section 4.3 |
| **3.2.4.1.2** Automated, operator-assisted calibration generating audit logs. | Complies. Calibration is automated and operator-assisted, and every calibration generates an audit log recording what was adjusted, when and by whom. Calibration is repeated at the manufacturer's intervals and whenever the calibration logs show drift. | System Architecture Section 3.8; Preliminary Project Plan Section 5.4 |
| **3.2.5.1** Each laser personalizes an entire card independently of other lasers. | Complies. Each integrated laser station receives the full card layout and the full data record for its card, and completes all marking on both faces without depending on any other station. | System Architecture Section 3.4; Preliminary Project Plan Section 4.3 |
| **3.2.5.2** Any laser station can be switched off or serviced without interrupting or degrading production. | Complies. Any laser station can be switched on, switched off or removed for maintenance while the line runs, and the workflow routes cards only to available stations. All stations are calibrated to identical quality, so output is unaffected, and this is demonstrated at factory acceptance by taking a station out during a run. | System Architecture Sections 3.4 and 3.8; Preliminary Project Plan Section 4.3 |
| **3.2.6.1.1** Submit machine datasheet with dimensions, weight, operating environment and system architecture. | Complies. The Machine Technical Datasheet is submitted, giving module dimensions (L x W x H: control module 48/96 x 70 x 85 cm; laser, input and output modules 48 x 70 x 140 cm), operating environment (15 to 40 degrees Celsius, 20 to 65 percent humidity) and Ethernet connectivity. The System Architecture describes each component. | Attachment: Laser personalization system datasheet; System Architecture Sections 3.1 and 3.9 |
| **3.2.6.1.2** Submit laser unit details: brand, model, type, technology, wavelength, lifespan, maintenance intervals. | Complies. The laser engraving units are Identis LX GEN 3 laser markers using Master Oscillator Power Amplifier fiber laser technology, up to four per machine. Wavelength, expected operational lifespan and maintenance intervals are stated in the Laser Engraving Unit Details submitted with the proposal. | Attachment: Laser personalization system datasheet; Attachment: Laser Engraving Unit Details; Preliminary Project Plan Section 5.4 |
| **3.2.6.1.3** Dedicated document on power requirements and air pressure, flow rate and compressor specifications. | Complies. Each personalization machine operates on 100 to 240 VAC at 50/60 Hz with a 2,500 W power supply, and includes an air compressor system for pneumatic transport and handling. Air pressure, flow rate and compressor specifications are set out in the dedicated Power and Air Pressure Requirements document. | Attachment: Laser personalization system datasheet; Attachment: Power and Air Pressure Requirements; System Architecture Section 3.1 |

## 3.3 Automated mailing and dispatch systems

| Requirement | Technical reasons supporting compliance | Cross-references |
|---|---|---|
| **3.3.1** Two mailing systems affixing one to four cards per carrier letter. | Complies. Two automated mailing and dispatch systems are supplied, installed and commissioned. Each attaches one to four cards to a single carrier letter, printed and affixed in the same pass so that the carrier is matched to its cards by data rather than by sequence. | System Architecture Sections 5.1 and 5.2; Preliminary Project Plan Section 4.3; Attachment: Mailing system datasheet |
| **3.3.2** Automatic conveyance of documents through the inserting module into envelopes. | Complies. After the cards are affixed and the match is verified, the carrier is folded in C, V or Z format and conveyed automatically through the inserting module into the envelope, which is then sealed. No manual handling occurs between affixing and insertion, and insertion is tested in the mailing system pre-commissioning test. | System Architecture Sections 5.1, 5.2 and 5.3; Preliminary Project Plan Section 4.5; Attachment: Mailing system datasheet |
| **3.3.3** Verification capabilities including 1D, 2D and QR code verification. | Complies. The verification station reads 1D, 2D and QR codes, and this is tested at factory acceptance. Each card is read twice against the job record, before its carrier is printed and again with its carrier after affixing, and any mismatch is diverted to the reject magazine instead of being inserted. | System Architecture Section 5.4; Preliminary Project Plan Section 4.3 |
| **3.3.4** Automatic printing of personalized carrier letters. | Complies. The carrier printing station prints each personalized carrier letter at the line immediately before the cards are affixed, including the destination address and dispatch reference, from content generated by the Mailing and Dispatch Management System. A4 and US letter formats up to 100 gsm are accepted. | System Architecture Sections 5.1, 5.2 and 6.9; Attachment: Mailing system datasheet |
| **3.3.5** Fully integrated card transport modules. | Complies. Each line includes fully integrated card transport modules that move cards from the input hopper to the affixing station under positional control, within a single integrated line from card reading to sealed and sorted mail piece. | System Architecture Section 5.1 |
| **3.3.6** Reject magazines for error handling. | Complies. Separate reject magazines receive the cards and carriers diverted out of the production path on verification failure. Rejected items are held under control and recorded against the job, so every card issued to the line is accounted for as a completed mail piece or a recorded reject. | System Architecture Sections 5.4 and 5.5; Attachment: Mailing system datasheet |
| **3.3.7** Buffer modules for uninterrupted operation. | Complies. Buffer modules hold work in progress between stations, so a brief stoppage at one station does not halt those upstream and downstream of it, and the line runs continuously under sustained load. Buffer operation is tested at factory acceptance. | System Architecture Sections 5.5 and 11.1; Preliminary Project Plan Section 4.3 |
| **3.3.8** Direct technology linkage with Malawi's ID database. | Complies. The mailing lines receive job data over a live interface from the Mailing and Dispatch Management System, which draws destination data from NRIS through the single integration gateway and reports packaged, dispatched and delivered status back to NRIS. As clarified in the Clarifications to Queries 005, the Purchaser provides the NRIS API. | System Architecture Sections 5.7, 7.1, 7.2 and 8.4 |
| **3.3.9** Compatibility with modern courier workflows. | Complies. The System generates a tracking reference for every mail piece and dispatch batch, exports structured dispatch data, records delivery status from an operator, and connects to its application programming interface or by secure file transfer. As clarified in the Clarifications to Queries 005, no postal operator is designated, and Inkript engages one and connects the System to it. | System Architecture Sections 6.9, 8.6 and 13.2 |
| **3.3.10** At least 2,000 completed mailers per hour across two machines. | Complies. The two mailing lines together produce not less than 2,000 completed mailers per hour, each line not less than 1,000. As clarified in the Clarifications to Queries 005, the rate is measured on single-card mailers. It is verified at factory acceptance and in the operational acceptance throughput test. | System Architecture Sections 5.6 and 11.1; Preliminary Project Plan Sections 4.3 and 4.6; Attachment: Mailing system datasheet |
| **3.3.11** Packed mailers handed to courier services for last-mile delivery to citizens' enrolment addresses. | Complies. Completed mail pieces are grouped into dispatch batches by destination, and each batch is closed with a handover record of contents, time and receiving party. As clarified in the Clarifications to Queries 005, no postal operator is designated, and Inkript engages the operator that delivers the cards and connects the System to its tracking service. | System Architecture Sections 8.2, 8.6 and 13.2 |
